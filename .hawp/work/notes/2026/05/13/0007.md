# Plan public shared standards absorption into HAWP

## Objective

Plan how HAWP should absorb only portable, reusable public shared standards from this repository into HAWP-owned destinations, with explicit boundary protection for private and project-specific content.

This is planning only. No standards are copied, no manifests are changed, and no install/update behavior is modified in this task.

- `shared_standards/public/**`

Explicitly excluded source trees:

- `shared_standards/private/**`

- `shared_standards/exports/**`
- `shared_standards/manifests/**`

Boundary note:

- Excluded paths may be referenced only as evidence for boundary verification; they are not candidates for absorption.
- `shared_standards/public/exports/**` is boundary-verification-only and must not be copied, summarized, adapted, or treated as source content.

Parallel work boundary note:

- Parallel working-tree changes are not automatic blockers.
- Parallel changes must be treated as lane boundaries.
- Continue scoped shared standards planning or implementation only when allowed paths do not overlap with unrelated modified or untracked paths.

## HAWP Destination Mapping

Primary destination groups:

- `core/.hawp/kit/references/**`
  - Candidate principles and standards references.
  - Expected sources: architecture/documentation/testing extracts, contract/boundary guidance, install/update safety reference.

- `core/.hawp/kit/patterns/**`
  - Evidence discipline and verification-oriented writing patterns.
  - Expected source: evidence-linked documentation principles.

- `core/.hawp/kit/templates/**`
  - Structured authoring artifacts and decision templates.
  - Expected source: ADR template (after light wording alignment).

- `core/.hawp/kit/usage/**`
  - Operational guidance when build/config practices are translated into workflow usage instructions.
  - Expected source: adapted build-and-env concepts only.

- `core/.github/instructions/**`
  - Reserved for later, explicitly approved chunks only.

- `core/.github/prompts/**`
  - Reserved for later, explicitly approved chunks only.

- `docs/**`
  - Human-facing reference pages and compatibility notes to avoid policy duplication across instruction files.

- `librarian/**` (tooling-only)
  - Only if a standard is transformed into validation/reporting logic, never as raw copied docs.

Absorption-pass overlay boundary:

- No `core/.github/instructions/**` or `core/.github/prompts/**` files should be created or modified during this absorption pass unless a later implementation chunk explicitly approves those exact paths.

## Boundary Rules

- No content from `shared_standards/private/**` is eligible for absorption.
- No content from `shared_standards/project-specific/**` is eligible for absorption.
- No content from `shared_standards/public/exports/**` is eligible for absorption as source material.
- No runtime implementation details are absorbed into HAWP standards.
- Public standards promoted into HAWP must be abstraction-first and repo-agnostic.
- HAWP prioritizes portability and safety boundaries over completeness.

Install/update distribution safety boundary:

- `shared_standards/public/standards/docs/hawp-install-update-safety.md` may be adapted only into reference-level HAWP guidance during this absorption pass.
- This pass must not modify:
  - `core/install.md`
  - `core/update.md`
  - `core/distribution/sources/**`
  - `core/distribution/generated/**`
  - install/update scripts
  - generated distribution files
- Any distribution-source, generated-guide, install-script, or update-script changes require a separate distribution-scoped task after absorbed reference guidance stabilizes.
