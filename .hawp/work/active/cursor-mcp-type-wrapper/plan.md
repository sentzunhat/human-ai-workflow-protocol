# cursor-mcp-type-wrapper — Cursor MCP: add `type: stdio` and `hawp-mcp` wrapper

**Type:** fix  
**Status:** plan-ready  
**Opened:** 2026-08-25  
**Target:** v0.0.11

## Input

Downstream install of hawp 0.0.9 with `--provider cursor`. Cursor never spawned
the server; status showed disconnected with no `createClient` call. Root cause:
`.cursor/mcp.json` generated by `hawp init --provider cursor` had neither
`"type": "stdio"` nor a resolvable command path.

Two separate problems:
1. Missing `"type": "stdio"` field — Cursor requires it explicitly.
2. `"command": ".hawp/bin/hawp"` is a relative path — Cursor's spawn cwd is
   not the repo root, so the binary is never found.

Evidence source: downstream install evidence 2026-08-25.

## Goal

`hawp init --provider cursor` generates a `.cursor/mcp.json` that Cursor
actually spawns. Also: ship a small `hawp-mcp` wrapper script alongside the
hawp binary that cds to the repo root before executing `hawp mcp`.

## Constraints

- Do not break Claude Code (`.mcp.json`) or Codex (`.codex/config.toml`) configs.
- The wrapper must be cross-platform (bash on macOS/Linux; `.cmd` or PowerShell on Windows).
- Use `${workspaceFolder}` interpolation for the command path if Cursor supports it; otherwise
  use an absolute path at `hawp init` time (same pattern as the Codex fix in v0.0.10).
- Do not add Content-Length framing — hawp MCP already speaks NDJSON (correct).

## Plan

### Step 1 — Investigate Cursor `${workspaceFolder}` interpolation

Determine whether Cursor expands `${workspaceFolder}` in `mcp.json` `command`
fields at spawn time. If yes, use it (portable, no absolute path needed).
If no, fall back to absolute path at `hawp init` time (reuse the `repoRoot`
pattern from v0.0.10).

Evidence needed: test `.cursor/mcp.json` with and without `${workspaceFolder}`;
check Cursor MCP docs or source.

### Step 2 — Write `hawp-mcp` wrapper

Ship a small `core/.hawp/bin/hawp-mcp` (bash) wrapper:

```bash
#!/bin/bash
set -e
REPO_ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
exec "$REPO_ROOT/.hawp/bin/hawp" mcp "$@"
```

On Windows: ship `hawp-mcp.cmd` (or document PowerShell equivalent).
The wrapper is distributed with the kit bundle and installed by `hawp init`.

### Step 3 — Update `writeMCPJSON` for Cursor

Add a `"type": "stdio"` field to the JSON written for Cursor. Claude Code and
Continue don't need it but it's harmless to include. Check whether adding it
breaks existing Claude Code `.mcp.json` reads.

Update `hawpServerEntry` (or make it provider-specific) to:
```json
{
  "type": "stdio",
  "command": "${workspaceFolder}/.hawp/bin/hawp-mcp"
}
```

Or, if `${workspaceFolder}` is not interpolated, use absolute path like v0.0.10.

### Step 4 — Update kit `usage/search.md` Cursor section

Add or update the Cursor MCP setup steps:
- Show the correct `mcp.json` shape
- Note: Customize → MCPs sidebar toggle (not Settings → Tools & MCP)
- Note: new chat / reload required after enable
- Note: tools appear as `project-0-<repo-slug>-hawp_*`

### Step 5 — Tests

- Unit test: `writeMCPJSON` for cursor includes `type: stdio` and resolvable command
- Integration check: `hawp init --provider cursor` generates working config in a temp repo
