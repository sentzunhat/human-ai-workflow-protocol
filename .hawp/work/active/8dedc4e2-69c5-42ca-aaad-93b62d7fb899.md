### Analysis

**Root cause (or most likely cause):**
_The code already has multiple CLI-shaped domains, but there is no product-level
contract for what the installable CLI is called, which commands belong to it,
and which repo-only maintenance actions must remain outside that surface._

**Directly verified:**
_`README.md` still describes `librarian/` as repo-local maintenance tooling.
`librarian/scripts/README.md` already has a clean domain map and boundary
pattern (`index.ts` / `cli.ts` / `script.ts`), which is a good base for a fuller
CLI surface. Zacatl documents application/domain/infrastructure/platform
layering, but its `ServiceType.CLI` platform currently throws not-implemented
errors and its docs recommend standalone dependency-injection helpers for
non-HTTP scripts today. `@oclif/core` can run the PoC command in source mode and
from a bundled CJS executable artifact; it warns when the current runtime is
below Node 26. Node 26 SEA docs support `--build-sea` with a config file and
warn that cross-platform SEAs must avoid code cache and snapshots._

**Inferred (not yet proven):**
_A durable next step is a Zacatl-aligned architecture note plus a package/bin
contract plan before any publish/binary work. The useful borrowing from Zacatl
is its layering and adapter discipline, not a runtime CLI dependency. For the
binary-shaped proof, CJS bundling is currently more reliable than raw ESM `tsc`
output or an ESM esbuild bundle._

**Scope — what else is affected:**
_`librarian/package.json`, `README.md`, `librarian/README.md`,
`librarian/scripts/README.md`, `.hawp/bin/hawp`, and any future npm `bin` entry._

## Outcome (filled at close)

Architecture note created:
`.hawp/work/notes/2026/07/08/librarian-cli-zacatl-architecture.md`.

The note proposes a Zacatl-aligned target shape with application command
modules, domain operations, infrastructure adapters, and a thin platform/bin
adapter, while preserving the existing repo-local wrapper and command-domain
structure.

PoC added under `librarian/scripts/hawp-cli-poc/`:

- `bin/hawp-poc.ts` is the executable boundary.
- `platform/cli/` owns routing and command registration.
- `application/commands/kit/validate.ts` is the oclif command adapter.
- `domain/kit/validate-kit.ts` delegates to the existing kit validation logic.
- `infrastructure/filesystem/hawp-repo.ts` owns repo/kit path resolution.
- `npm --prefix librarian run cli:poc:bundle` builds
  `librarian/build-bin/hawp-poc.cjs` as a disposable executable artifact.
- `npm --prefix librarian run cli:poc:binary` attempts a Node 26 SEA binary for
  the current host.
- `npm --prefix librarian run cli:poc:binaries -- --target all` writes a target
  manifest for Linux x64/ARM64, macOS x64/ARM64, and Windows x64/ARM64.
- `.github/workflows/hawp-cli-poc-binaries.yml` builds the target matrix on
  matching GitHub-hosted runners and uploads binary artifacts.
