### Input (what was reported)

> Make sure it is easy to create a UUID and make it easier for the AI/digital agent
> to use these tools. If we need a script, add it to the hawp bin —
> e.g. `hawp generate uuid`.

---

### Context

Since UUID Phase 1–2, new work items are UUID-native, but generating one requires the
raw incantation `node -e "console.log(crypto.randomUUID())"` documented in templates.
A first-class `hawp` subcommand is easier to remember, shows up in the wrapper's usage
text, and gives agents one canonical tool.

---

### Recommended Fix

1. Add `uuid` subcommand to `.hawp/bin/hawp` (`hawp uuid`, alias `hawp generate uuid`):
   prints a full UUID v4 to stdout; `--short` prints the 8-char display form.
   Implemented inline with node (repo already requires node >= 26); no librarian dependency.
2. Add npm script `uuid` in `librarian/package.json` for npm-first workflows.
3. Update templates (`intake-plan.md`, `work-intake.md`) and `usage/intake-workflow.md`
   to reference `./.hawp/bin/hawp uuid` as the primary way.
4. Update wrapper usage text and `librarian/README.md` command table.

**What to verify after:**

- [ ] `./.hawp/bin/hawp uuid` prints a valid UUID v4; `--short` prints 8 hex chars
- [ ] `./.hawp/bin/hawp generate uuid` alias works
- [ ] Full validate suite passes
