### Context

The repo is current on `dev` and `origin/dev`, and Active Work was empty at the
start of this pass. While tracing the next backlog item ("Verification clarity
push"), two concrete usability gaps showed up:

1. `work:validate` currently reports `Proven: 142/228` but gives no file-level
   visibility into the 18 closed plans whose checklist-style verification lines
   lack `Evidence:` or an explicit unproven marker.
2. `./.hawp/bin/hawp work normalize --dry-run --validate` currently routes into
   the apply-mode npm shortcut (`work:normalize`) and exits with the mutual
   exclusivity error `--dry-run and --apply are mutually exclusive`.

Both gaps make the tooling harder for agents to use safely: one hides exactly
which records need cleanup, and the other breaks the advertised dry-run flow.

---

### Analysis

**Root cause (or most likely cause):**
_`verification-clarity.ts` only tracks evidence-backed vs explicitly unproven
checklist lines, without listing ambiguous checklist claims. Separately, the
`hawp` wrapper delegates `work normalize` to an npm script that hardcodes
`--apply --validate`, so extra CLI flags cannot override the mode._

**Directly verified:**
_`git fetch origin` shows `dev` and `origin/dev` at the same commit
`a2a28fbe6bcd3f660eed6a20c962c6f06066f020`. `npm --prefix librarian run
work:validate` passes, with verification clarity at `142/228`. An ad hoc scan
found 18 closed plans with checklist lines lacking `Evidence:` / explicit
unproven labeling. `./.hawp/bin/hawp work normalize --dry-run --validate`
currently exits 2 with `Error: --dry-run and --apply are mutually exclusive.
Choose one.`_

**Inferred (not yet proven):**
_`work-normalize` likely still has legacy-ID assumptions in its detection path,
so any new verification-clarity guidance there should be made UUID-aware while
we are in that code._

**Scope — what else is affected:**
_`.hawp/bin/hawp`, `core/.hawp/bin/hawp`, `librarian/package.json`,
`librarian/scripts/hawp/work-validate/**`, `librarian/scripts/hawp/work-normalize/**`,
and the docs that describe how to run normalize/validate._

### Recommended Fix

1. Make verification clarity actionable:
   - teach `work:validate` to report ambiguous checklist claims separately from
     evidence-backed and explicitly unproven ones
   - add a `work-normalize` blocked rule that points at closed plans whose
     verification checklist lines need `Evidence:` or an explicit unproven label
2. Make the wrapper honor real normalize CLI flags:
   - route `hawp work normalize` / `hawp backlog upgrade` through the raw
     TypeScript CLI rather than the apply-mode npm shortcut
   - keep the npm shortcut available as the apply-with-validate convenience path
3. Update docs/tests so agents can discover the right dry-run vs apply entry
   points and the new verification-clarity reporting.

## Outcome (filled at close)

Delivered 2026-07-03.

1. **Normalize wrapper now honors real CLI flags.**
   - Added `work:normalize:cli` in `librarian/package.json` for the raw
     `backlog upgrade` contract.
   - Kept `work:normalize` as the convenience apply shortcut
     (`--apply --validate`).
   - Updated `.hawp/bin/hawp` and `core/.hawp/bin/hawp` so
     `hawp work normalize ...` and `hawp backlog upgrade ...` route to the raw
     CLI, which restores the documented dry-run behavior for agents.

2. **Verification clarity now reports ambiguous checklist claims explicitly.**
   - `work:validate` now separates evidence-backed claims, explicitly unproven
     claims, and ambiguous checklist claims lacking `Evidence:` or an explicit
     unproven label.
   - Output is capped to a readable sample with a remainder count, so the
     warning stays actionable instead of dumping the entire archive.

3. **`work-normalize` now flags weak closed-plan verification records and handles
   UUID-native plan IDs on the detection path.**
   - Added blocked rule `B7` for ambiguous closed-plan verification checklist
     claims.
   - Updated normalize backlog parsing / plan scanning to recognize UUID cells,
     UUID plan fields, and short UUID display forms in the current backlog
     layout.

4. **Docs/tests updated for agent discoverability.**
   - `librarian/README.md` and `scripts/hawp/work-normalize/CLI.md` now
     distinguish the raw CLI from the apply shortcut.
   - Added test coverage for ambiguous verification warnings and UUID-native
     normalize detection.
