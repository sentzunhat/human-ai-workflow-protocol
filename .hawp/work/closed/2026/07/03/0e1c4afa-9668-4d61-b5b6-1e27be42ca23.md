### Context

Phase 1 requires the full 36-char UUID in backlog cells, which is noisy in tables.
The Recently Closed row for Phase 1 already shows how wide it gets. Prefix matching
lets rows carry `` `0e1c4afa` `` while plan files stay `<full-uuid>.md`.

The legacy warning file is a status report for TASK-011, misclassified as an untyped
plan because its filename has neither an ID nor a supporting suffix.

---

### Analysis

**Directly verified:**

- `id-parser.ts` rejects 8-char short forms by design (Phase 1 test asserts null).
- `backlog-consistency.ts` matches rows to files via exact `${id}.md` plus
  case-insensitive substring; orphan detection compares extracted file IDs against
  row IDs with exact `Set.has`.
- Supporting-file classification skips filenames ending in `-summary`, `-status`,
  `-status-report`, `-checkpoint`, `-evidence`.

**Scope:**

- `librarian/scripts/hawp/work-validate/validations/id-parser.ts` — add
  `extractShortUuid` + `idsMatch` helpers.
- `librarian/scripts/hawp/work-validate/validations/backlog-consistency.ts` — use
  prefix-aware matching for file finding and orphan detection.
- `librarian/scripts/hawp/work-validate/orchestrate.ts` — accept a short-UUID cell as
  a valid row ID.
- `.hawp/kit/usage/intake-workflow.md` — lift the "full UUID only" restriction.
- Rename the TASK-011 status file to a classifiable name.

---

### Recommended Fix

1. `idsMatch(a, b)`: true when equal (case-insensitive), or when one side is exactly
   8 hex chars and the other is a full UUID starting with it.
2. Row parsing treats an exact 8-hex cell as a short-UUID ID.
3. Consistency checks use `idsMatch` instead of exact/substring compares where IDs meet.
4. Rename `2026-04-26-hawp-adr-template-review.md` →
   `2026-04-26-TASK-011-adr-template-review-status.md` (it is a status report).
