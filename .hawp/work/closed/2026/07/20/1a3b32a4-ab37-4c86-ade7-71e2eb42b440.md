---

### Analysis

**Root cause (or most likely cause):**
_The desire is valid, but the first useful runtime path is not WebGPU. The repo
needs a small Node/library proof using Transformers.js with WASM and a shared,
configurable filesystem cache/model directory._

**Directly verified:**
_Transformers.js documents the `pipeline` API and allows a model id or path as
the second argument. Its environment API exposes `localModelPath`, `cacheDir`,
`useFS`, `useFSCache`, and Node-environment/filesystem flags. The docs still
describe WebGPU as a separate optional device path, but this item no longer
needs WebGPU to be the center of the proof. `onnxruntime_go` exposes ONNX
Runtime session thread controls for intra-op and inter-op CPU parallelism.
ONNX Runtime documents CPU thread-pool behavior. An ONNX MiniLM embedding model
exists with 384 dimensions and an approximately 0.08 GB model file._

**Inferred (not yet proven):**
_This lane should pivot away from Node-only runtime assumptions. The likely
shape is a small Go CLI/library binary with optional cached ONNX Runtime assets
and cached ONNX models. Embeddings should come before text2text/generation,
because semantic search has a smaller runtime surface than autoregressive or
encoder-decoder generation._

**Scope — what else is affected:**
_Dependency policy, command UX for model downloads, shared home-folder cache
layout, per-repo override behavior, cross-platform support promises, the future
database/index layout for `work/` and `kit/`, and any future AI helper library
under librarian._

---

### Recommended Fix

- Build a minimal Node proof that imports Transformers.js and runs a tiny WASM
  pipeline.
- Use a shared filesystem cache/model layout, with a proposed default such as
  `~/.hawp/models` or `~/.hawp/cache/models`.
- Support explicit override by env var or config, so repos can change the model
  location without editing code.
- Record offline/reuse behavior after the first download.
- Downgrade WebGPU to "out of current scope" unless a future item explicitly
  asks for it.
- Add a Go librarian model strategy: model registry/download/cache commands,
  CPU-only ONNX embeddings, bounded Go worker pools, and ONNX thread settings.
- Add the product-layer command/story: `db init`, migrations, work/kit ingest,
  lexical/vector index build, `context` commands, and local handoff summaries.
- Treat text2text/generation as optional and later; prefer extractive summaries
  from ranked chunks first.

**What to verify after:**

- [ ] Minimal Node/WASM proof runs with `transformers.js`

- [ ] Per-repo override path is proposed

      packaging
- [ ] Model install/load/settings commands are designed without embedding model
      files in the binary
- [ ] Work/kit ingest + DB/index lifecycle commands are explicit
- [ ] Local context/handoff flow is explicit for larger-model prompting
