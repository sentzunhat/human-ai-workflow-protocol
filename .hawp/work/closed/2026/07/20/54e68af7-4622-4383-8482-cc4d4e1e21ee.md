### Input (what was reported)

> Plan for a CLI that could be made into a binary using Node.js.
>
> 2026-07-08 update: do not assume AI models are embedded into the binary. Prefer
> a shared user-level model/cache folder that multiple repos can reuse and
> override.

---

### Context

This is the packaging spike spun out from
`1c2db85b-d57b-47a1-8c4b-b28dc55f2d5c`.

Node SEA is now real enough to take seriously, but it is still active
development and the repo has not yet tested how native modules, shared model
artifacts, and cross-platform release mechanics would fit that path.

---

### Analysis

**Root cause (or most likely cause):**
_The packaging question is separate from the runtime/model question. A binary
strategy that embeds models by default would create large release promises that
the repo does not need yet._

**Directly verified:**
_Node’s official SEA docs support `--build-sea` and embedded assets, but mark
the feature `Stability: 1.1 - Active development`._

**Inferred (not yet proven):**
_The most likely friction points are native dependencies, first-run model
downloads, user-level cache layout, per-repo overrides, and platform-specific
release automation._

**Scope — what else is affected:**
_Release docs, packaging scripts, cache/model strategy, install/update story,
and possibly whether binary distribution is even the right first deliverable._

---

### Recommended Fix

- Write the packaging decision matrix first.
- Separate "single executable" from "self-contained AI runtime with bundled
  models".
- Prefer a user-level shared model/cache folder over bundled model assets unless
  a later proof shows bundling is necessary.
- Decide whether the first binary target is wrapper-only, CLI-only, or
  model-cache-aware.

**What to verify after:**

- [ ] SEA constraints are documented
- [ ] Shared asset/model strategy options are explicit
- [ ] Cross-platform release assumptions are called out

---

## Outcome (filled at close)

Closed 2026-07-20, resolved by decision rather than further spiking. The
packaging question is answered by the Go-first direction: a small static Go
binary (~1.6 MB proof, `librarian/go/`, cross-compiled via `make dist` for
macOS/Linux/Windows x64+arm64) with no embedded models. The
"shared user-level model/cache folder" preference this spike recorded became
the `~/.hawp/` provisioning design in `e98de8c4`; release mechanics live in
`cdcf9f78`. Node SEA is not pursued.

## Verification (filled at close)

- Evidence: `make dist` in `librarian/go/` produced all six platform
  binaries at ~1.6-1.7 MB on 2026-07-20.
- Evidence: successor plans `e98de8c4` (asset provisioning) and `cdcf9f78`
  (release/update) cover this spike's open questions.
- The verify checklist items (SEA constraints, asset strategy options,
  cross-platform assumptions) are addressed by decision records rather than
  a Node SEA proof; SEA-specific documentation is explicitly not needed.
