### Context

The user reports that the generated `update-dev` workflow is not reliably applying dev-branch updates in practice. They also asked for full intake workflow handling and automatic regeneration of distribution files.

---

### Analysis

**Root cause (or most likely cause):**
The generated install/update scripts only source content from remote GitHub archives. This makes local branch changes invisible until pushed and can look like update-dev is not updating, especially when validating in this repo or while testing branch commits before push.

**Directly verified:**

- Distribution variants are generated by `librarian/scripts/distribution/shared/composition.ts` and rely on a single script source plus branch REF substitution.
- `core/distribution/sources/update/script.md` and `core/distribution/sources/install/script.md` currently pull from remote archive only.
- Generated `update-dev.md` correctly pins `REF="dev"`, but source mode is still remote-only.

**Inferred (not yet proven):**

- Supporting explicit local source mode (opt-in env variable) will remove ambiguity and make branch validation predictable in any repo, including this one.
